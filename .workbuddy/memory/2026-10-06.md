## 局域网互传（LTP/1）项目从零到可运行

工作区：`D:/win-shouji-huchuan`。需求：Windows 电脑端 + Android 手机端，局域网内互传文件，无外网服务器。

### 架构决策
- **协议单一事实来源**：`shared/protocol.js`（CommonJS）。电脑端直接 `require`；手机端通过 `scripts/gen-protocol-mjs.js` 机械转换为浏览器 ESM（`shared/protocol.mjs`，自动生成勿手改），保证两端字节级一致。
- 协议层做了**同构改造**：文件顶部注入 Buffer 垫片（浏览器无 Buffer 时）+ 用 `globalThis.Buffer` 取用避免 TDZ 遮蔽 + crypto 分支按 `IS_NODE` 隔离。**坑：本地变量命名 `Buffer` 会触发 "Cannot access 'Buffer' before initialization"**，必须用别名（本项目用 `Buf`）。
- 端口：TCP 53317、HTTP/WS 网关 53318（= TCP+1）、UDP 53317 组播发现（239.255.42.99）。
- 二进制帧格式：`magic "LTPC"(4B) | fileIdLen(2B) | fileId | seq(4B) | payloadLen(4B) | payload`，头部固定 14+fileIdLen 字节；首字节 `{`=文本、`L`=二进制。

### 两端
- **电脑端 Electron 33**：discovery.js（组播+网段扫描）、server.js（TCP 会话 + 手写 WebSocket 网关 `encodeWsFrame/decodeWsFrame`）、transfer.js（分片收发/断点续传）、main.js（22 IPC）、preload（26 API）、renderer 深色卡片 UI（5 标签页）。

## 桌面端打包（electron-builder / NSIS）

### 关键坑：`extraResources.from` 路径基准
- `extraResources` 的 `from` 是**相对本包 `package.json` 所在目录**解析（即 `desktop/`），不是相对 `build` 字段。
  最初写成 `"../../shared"` → 解析为 `D:\shared`（不存在）→ **electron-builder 只打 warning 不报错，直接产出一个缺协议层的 app.asar**，装完一启动就 `Cannot find module protocol.js`。
  正确写法：`{ "from": "../shared", "to": "shared" }` → 落到 `resources/shared/protocol.js`。
- 另需补 `package.json` 的 `author`（否则 electron-builder 警告 "author is missed"）。

### Windows 文件锁与清理
- `release/win-unpacked/邻传.exe`（180MB）会被 Windows Defender 实时扫描锁定，**二次打包报 `app.asar 被占用`** → 换新输出目录绕开：`--config.directories.output=release-v2`。

- **`--remote-debugging-port` 对打包产物要「直接传给 exe」**，不能用 `ELECTRON_CLI_ARGS`
  （那是 electron-vite 开发期的机制，打包后不生效）。且必须在 `unset ELECTRON_RUN_AS_NODE` 之后。
- 启动后 `--remote-debugging-port` 生效时会在 stderr 打 `DevTools listening on ws://...`，
  可作为「这次真的进 GUI 模式了」的判据。

  → `{"ok":true,"name":"...","protocol":"LTP/1"}`。

### 验证（`scripts/verify-font-about.js`，30 项全绿）
- **教训：判断中文字体是否生效不能用宽度对比** —— 汉字在思源黑体与回退字体里都占固定 1em 宽（等宽方块字），`getBoundingClientRect` 和 canvas `measureText` 对任何字体都返回完全相同的值（实测 288/624/200 三组全都一样），必然误判成「字体没生效」。
- **正解：统计 canvas 墨迹像素** —— 画到 canvas 后 `getImageData` 数 `d[i]<128` 的深色像素。实测（80px「邻传设备」）：`450→7716, 700→10514, 900→12546` 单调递增，同时证明字体被选中 + 可变轴生效。
- 另一个坑：`performance.getEntriesByType('resource')` 在 `file://` 下对字体返回 `[]`（Resource Timing 不填），改用主动 `fetch(...).arrayBuffer()` 读前 4 字节校验 magic `77 4f 46 32`（"wOF2"）。
